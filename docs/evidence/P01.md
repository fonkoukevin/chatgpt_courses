### Ce que couvrent les cinq tests API

HTTP réel vers Spring et PostgreSQL réel via Testcontainers : sonde UP sans session anonyme, migration Flyway appliquée, persistance des attributs de session et suppression en cascade, vrai 404 Problem, refus 401 et mutation sans CSRF refusée 403. La pause réelle du conteneur PostgreSQL provoque un 503, puis sa reprise rétablit UP. Aucune substitution H2 et aucun test ignoré pour obtenir le résultat.

Le test de panne utilise pause/reprise : Docker Desktop changeait le port éphémère sur stop/start. Le test de persistance Compose vérifie séparément un véritable redémarrage avec volume conservé.

## Défauts observés et corrigés

- Réseau Compose `internal:true` : conteneurs sains mais ports hôte réellement injoignables. Remplacement par un bridge dédié et bindings loopback, avec recréation des conteneurs/réseau sans suppression des volumes.
- Sélection/quotage Windows : `npm.ps1` bloqué par la politique existante ; sélection de `.cmd`. Lancement du Wrapper via Node corrigé avec arguments Windows adéquats. Aucun changement de politique système.
- Dépendance de lint `minimatch` : dix alertes modérées issues d’une seule faille. Substitution ciblée vers 11.0.1, mise à jour explicite puis `ci`, audit et contrôles réels du lint. Aucun changement de stack ou contrôle désactivé.
- Turbopack détectait un fichier de workspace parent extérieur au dépôt. Racine ancrée explicitement sur ce projet ; aucun fichier parent modifié.
- Arrêt/démarrage : surveillance des sorties dès le lancement, code d’échec propagé, groupes dédiés Linux, confirmation de disparition avant effacement du suivi, traitement d’une course entre arrêts concurrents. L’exécution locale prouvée reste Windows ; Linux sera observé lors d’une vraie CI.
- Isolation : `.env.local` n’est chargé que pour local ou environnement absent. Un `BASE_URL` hérité ne peut plus détourner le smoke vers une autre origine.
- Profil test : port `${API_PORT:0}` pour permettre le smoke CI sur 8080 ; les tests `RANDOM_PORT` conservent leur port aléatoire, confirmé par le dernier verify.
- Diagnostics : variable hôte `DEBUG` retirée de l’environnement enfant Spring, `--debug=false`, propriétés d’erreur Boot 4 adaptées ; réponses publiques sans stack ou URL JDBC.
